## 通知与可靠投递边界

可选高级模块已提供邮件、企业微信和站内渠道、管理员事件规则及显式产品经理绑定，可选择单渠道或多渠道。基础验证码用途与业务通知隔离；[公共邮件传输边界](https://github.com/prototype-hub/proto-bridge/pull/57)和[前端讨论扩展入口](https://github.com/prototype-hub/proto-bridge-ui/pull/72)已合并，这两个入口本身不包含完整高级通知。阿里云短信仍待实现。

当前业务事件为客户新批注、客户追评及成员公开回复。成员公开回复仅通知已验证、主动逐线程订阅的原作者，内部备注不对外发送。发送前重新核对当前权益、账号、项目权限与收件人绑定，订阅和产品经理绑定均不扩大原有访问权限。

已提供模板、用户绑定、个人站内收件箱、静默与汇总及逐渠道发送记录。仅明确发生在发送前的瞬态失败自动有限重试；结果未知时由有权管理员核对后受控恢复，已受理渠道不重发；部分成功时只恢复失败或未知渠道。启动或恢复不补发历史事件，供应商受理也不等于实际送达或已读。

已完成受控 SMTP 投递及企业微信配置测试；业务企业微信实发与目标部署环境仍需分别核验，不能据此视为全部供应商与场景已验收。

## 离线授权实现边界

已提供安装请求下载、凭证导入、本地验签与声明查询，相关实现已合入[后端](https://github.com/prototype-hub/proto-bridge/pull/38)和[前端](https://github.com/prototype-hub/proto-bridge-ui/pull/49)。配套离线工具已支持签发、递增换证、订单幂等和历史原凭证导出，仅供可信单操作员在本机使用，不内置于客户运行端，也不提供购买或付款流程。

验签结果与当前实际准入分别读取。配套高级容量模块按全局项目总上限 P 与统一每项目逻辑版本总上限 V 执行永久扩容，适用于现有、新增和恢复的项目。P、V 可独立提高并保留另一维，均为完整绝对上限，不与免费 5/5 相加，也不再按指定项目发放版本块。统一声明与界面已合入[后端](https://github.com/prototype-hub/proto-bridge/pull/49)和[前端](https://github.com/prototype-hub/proto-bridge-ui/pull/61)。客户端读取服务端实际容量，不按声明自行推算；高级功能另需对应模块可用、显式 feature 授权及有效权益，容量扩容不自动授予全部高级功能。

免费基础版默认 5 个项目、每项目 5 个逻辑版本；缺少有效凭证或未加载高级容量模块时回到免费容量，已有超额数据保留，仅限制新建项目及新建、恢复版本。保留项目含回收站均占项目额度，项目恢复沿用名额、不重复占用；依赖数据与文件清理完成、项目根记录移除后才释放。维护期到期或试用结束不会撤销永久容量。免费基础版无须安装高级模块即可创建项目并使用基础功能，基础浏览、分享与邮箱身份验证码不依赖商业凭证，接口行为见[安装凭证验证](https://github.com/prototype-hub/proto-bridge/blob/main/doc/public/API.md#installation-credential-verification)。

当前支持 schema 2 与 schema 3 凭证，schema 1 显示不支持。首次成功导入有效 schema 3 试用凭证即开始固定 **30×24 小时**计时，即使尚未安装高级模块；重放、换证或重启不重置。到期停止试用权益，基础与已有永久权益保留。公共接口和状态展示已合入[后端](https://github.com/prototype-hub/proto-bridge/pull/51)和[前端](https://github.com/prototype-hub/proto-bridge-ui/pull/63)，这些链接仅说明公共配套接口与展示。升级前需停旧节点并联合备份，按[安装凭证运维说明](https://github.com/prototype-hub/proto-bridge/blob/main/doc/public/OPERATIONS.md)配套切换，不自动迁移或清除安装身份、接受记录与业务数据，也不能靠重新签发绕过旧接受记录。

## Java 本地同步客户端边界

客户端绑定已有逻辑版本并监听已导出的 HTML 目录，生成稳定快照后打包上传；保留原包与原请求键处理断线、未知结果及重启恢复，版本冲突后由用户明确重基，配对可撤销。公共配套能力已合入[后端](https://github.com/prototype-hub/proto-bridge/pull/52)和[前端版本工具入口](https://github.com/prototype-hub/proto-bridge-ui/pull/64)。客户端不读取 `.rp`，也不采集 Axure 本地预览。

首个操作系统为 Windows，已在 Windows 10 虚拟机完成原生流程验证，提供源码及自带运行时的 app-image 构建入口。MSI 安装包、签名、自动升级、真实客户 Axure 包及其他操作系统尚未完成验证。

## 自动截图与视觉对比边界

对同一逻辑版本的两份固定修订页面创建持久任务，生成双侧截图、像素差异图与统计，支持私有下载、显式重试及清理；[公共比较工具入口](https://github.com/prototype-hub/proto-bridge-ui/pull/65)已配套合并。

当前仅支持 **1440×900 或 390×844、DPR 1**，在隔离容器中使用离线资源。功能默认关闭，部署者须配置可信 worker；结果表示指定视口的像素变化，不推断 HTML 语义、评审结论或批准状态。

## 企业单点登录边界

已实现单一 OIDC 的既有平台账号显式映射、版本化启停与解绑、专用会话撤销、平台退出与显式组织退出，并保留密码管理员恢复入口。[公共登录工具入口](https://github.com/prototype-hub/proto-bridge-ui/pull/67)已配套合并。

当前已验证 Keycloak，支持 RS256 与 `client_secret_post`，端点限定于同一 issuer 来源；其他身份提供方需分别验证。不会自动注册账号、按邮箱认领或同步角色，映射本身不扩大已有项目权限。

现有权限内统计与分享访问计数仅展示存量和访问次数，不等于独立人数、任务完成分析、流失分析或行为漏斗；“用户研究与行为漏斗”仍为规划功能。
